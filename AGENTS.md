# Resonance

Monorepo with `backend/` (Python FastAPI) and `client/` (Kotlin Multiplatform / Compose).

## Backend (`backend/`)

- **Entrypoint**: `backend/main.py` — run with `uvicorn main:app --reload` from `backend/`
- **Config**: `config.py` uses `pydantic-settings` — create `backend/.env` from `.env.example` with
  `OLLAMA_BASE_URL`/`OLLAMA_MODEL`/`OLLAMA_NUM_CTX` (local Ollama, native API) and `DB_PASSWORD`
- **Endpoints**: `POST /sessions` creates a session; `POST /sessions/{id}/exchanges` accepts file upload, returns
  analysis
- **Architecture**:
    - Uploaded audio saved to temp file, deleted in `finally`
    - `stt.py` → whisper "base" model → raw transcript → local Ollama (`llama3.1`) for analysis
    - Ollama is called over its native API (`/api/chat`) with `num_ctx` (default 8192) so long entries and
      multi-exchange titles are not silently truncated; JSON output is enforced via `format: "json"`
    - On LLM failure/timeout, the exchange is still created with an empty reflection (graceful degradation);
      the exchange is never partially created
    - Session titles are generated by the same Ollama model when a session ends; an empty title is not stored
- **Validation**: Only `.wav`/`.mp3` allowed (checked by MIME type); empty files rejected
- **Testing**: No test framework configured — use `curl` or `test_main.http` (JetBrains HTTP client)

## Client (`client/`)

- Kotlin Multiplatform with Compose — targets Android (`androidApp`) and Desktop JVM (`desktopApp`)
- Shared code in `client/shared/src/commonMain/`
- **Desktop hot reload**: `./gradlew :desktopApp:hotRun --auto` from `client/`
- **Desktop run**: `./gradlew :desktopApp:run`
- **Android build**: `./gradlew :androidApp:assembleDebug`
- **Tests**: `./gradlew :shared:jvmTest` (Desktop), `./gradlew :shared:testAndroidHostTest` (Android)
- Requires JDK 17+ and Android SDK for Android builds

## Code Style Rules

- **Type hints everywhere** — every function parameter, return type, and variable should be typed. Redundant types are
  better than missing ones
- **Explicit nullability** — nothing is `| None` without a clear reason. If something is nullable, be ready to explain
  when and why it can be None
- **Files are promises** — a file named `exchanges.py` contains only exchange related code. anything that doesn't match
  the
  filename goes in the appropriate file
- **No surprise dependencies** — do not add any new dependencies without explicit permission. if you want to add
  something, ask first, explain what it does and why it's needed, and wait for approval
- **Readability first** — if a line needs to be read twice to be understood, rewrite it. no clever one-liners that
  sacrifice clarity
